# 지식베이스

여기에 넣은 문서가 봇 답변의 **유일한 근거**다 (계획서 §1).
모델의 일반 지식으로 답하지 않는다.

## 형식

- 마크다운(`.md`) 또는 텍스트(`.txt`)
- 파일 하나에 주제 하나
- `## ` 제목 단위로 청크가 나뉜다 — 제목을 질문처럼 쓰면 검색이 잘 된다

## 화면(스크린샷) 붙이기

"이 화면에서 ○○를 누르세요" 류의 답은 **화면 속 글자가 검색어**다. 수강생은
화면에 뜬 문구를 그대로 받아 적어 묻기 때문이다 ("command not found 라고 떠요").

`images/` 에 그림을 넣고, 조각 안에서 한 줄로 가리킨다:

```markdown
## 터미널에서 명령어가 먹히지 않을 때

![화면](images/path-오류.png)

터미널을 껐다 켜고 다시 해 보세요. 설치는 됐는데 경로가 아직 안 잡혀서 그렇습니다.
```

색인할 때 macOS 내장 글자 인식(Vision)으로 그림 속 글자를 읽어 **검색에만**
쓴다. 세 가지를 알아 두면 된다.

- **그림은 기기 밖으로 나가지 않는다.** 인식은 이 맥 안에서 끝난다.
- **화면 속 글자는 답변 근거가 아니다.** 인식 결과에는 아이콘에서 나온
  부스러기가 섞이는데, 그게 근거에 들어가면 봇이 그걸 사실처럼 옮긴다.
  화면을 설명해야 하면 **본문에 직접 쓴다.**
- **그림을 바꿔 끼우면 저절로 다시 읽는다.** 파일 내용이 기준이라 이름을
  바꾸거나 옮기는 것만으로는 다시 읽지 않는다 (`.ocr-cache.json`).

수강생이 **질문과 함께** 올린 사진은 봇이 카카오톡 '저장하기'로 받아 글자를 읽고 곧바로
지운다 (`[photo] enabled`, docs/screenshots.md). 그 글자도 검색에만 쓴다.

## ⚠️ 주의 — 여기 넣는 자료도 검수 대상이다 (계획서 §6-6 5항)

RAG 문서에 인젝션 문구가 섞이면 그대로 LLM 프롬프트에 들어간다.
외부에서 받은 문서를 그대로 넣지 말고 내용을 확인한 뒤 넣는다.

## 이 폴더는 예시다

`scripts/setup.sh` 가 처음 한 번 `data/knowledge/` 로 복사한다. 봇이 읽는 곳은
`data/knowledge/` 이고, 그 폴더는 git 에 올라가지 않는다 (운영하는 강의의 실제 자료가 들어가므로).
예시 문서(수강료·환불·수업 운영·화면 붙이기)는 **지어낸 내용**이다 — 운영 전에 실제 자료로 바꾼다.
