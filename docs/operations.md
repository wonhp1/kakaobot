# 운영 가이드 — 메뉴바

> 처음에는 시험용 방(다른 사람 한 명을 초대한 오픈채팅)에서 **연습 모드**로 돌려 보고 실제 방으로 옮긴다.
> 방을 바꾸려면 `config/config.toml` 의 `[room] name` 과 `~/.config/openkakao/config.toml` 의
> 전송 허용 목록(`allowed_send_chats`)을 함께 바꾼다. 설치는 README · `bash scripts/setup.sh`.

## 띄우기

```bash
bash scripts/menubar.sh
```

화면 오른쪽 위에 🤖 아이콘이 생긴다. Dock 아이콘은 없다. 메뉴바는 봇의 **리모컨**이다 —
메뉴바를 닫아도 봇은 계속 돌고, 봇이 죽어도 메뉴바는 남는다.

⚠️ 봇은 메뉴바를 띄운 앱의 **손쉬운 사용 권한**을 이어받는다. 권한을 준 곳(터미널·Claude 앱 등)이
아닌 곳에서 띄우면 봇이 카카오톡 창을 읽지 못한다 (`docs/permissions-setup.md`).

## 아이콘

| 아이콘 | 뜻 |
|---|---|
| 🤖⚪ | 봇 꺼짐 |
| 🤖🧪 | 실행 중 · **연습 모드** — 판단은 하지만 보내지 않는다 (audit 에 `via=dry-run`) |
| 🤖🟢 | 실행 중 · **실제 전송** |
| 🤖⏸ | 긴급 정지 중, 또는 설정 파일 오류 |
| 🤖💬 | 답변 만드는 중 (첫 질문은 임베딩 모델 로딩으로 10초 이상) |
| 🤖💤 | 방 창이 화면에 없어 기다리는 중 (닫힘·최소화·다른 데스크탑) — 돌아오면 그사이 질문에 답한다 |
| 🤖⏳ | 45초 넘게 신호 없음 — 멈췄을 수 있다 |
| 🤖🔴 | 오류로 멈춤 (서킷 브레이커 등) — '마지막 오류'를 눌러 확인 |
| ⚠️ 추가 | 자가진단(canary) 실패 |

## 메뉴

| 항목 | 하는 일 | 반영 시점 |
|---|---|---|
| ⏸ 긴급 정지 / ▶︎ 답변 재개 | `enabled` 전환. 확인 없이 바로 | 다음 폴링(최대 1분) 때, 그리고 **보내기 직전**에 다시 확인. 쉬는 동안에는 아무것도 보내지 않는다 |
| 실제 전송 켜기… / 연습 모드로 | `dry_run` 전환. 켤 때만 확인창 | 같음 |
| 답변 엔진 ▸ | claude -p / API / 로컬 LLM. 로컬은 `[local]` 을 채우기 전엔 막힌다 | 다음 질문부터 |
| 답변 엔진 ▸ 엔진 점검 | 시험 질문 3개 (근거대로 답하나 · 근거 없으면 거절하나 · 지시 주입을 따르지 않나) | — |
| 답변 방식 ▸ | 댓글 / 일반 메시지 | 다음 답변부터 |
| 봇 시작 / 중지 | 봇 프로세스를 띄우거나 끝낸다. 20초 넘게 안 끝나면 강제 종료를 권한다 | — |
| 열기 ▸ | 오늘 처리 기록 · 운영 로그 · 봇 실행 오류 기록 · 설정 파일 · 지식베이스 폴더 · 로컬 LLM 안내 | — |

- **재개해도 옛 질문에는 답하지 않는다.** 정지 중에 들어온 메시지는 기준선에만 반영된다.
- **정지를 누른 순간 LLM 이 답을 만들고 있었다면** 그 답은 보내지 않는다 (`cancelled`).
- 설정 파일을 직접 고치다 문법이 깨지면 봇은 **답하지 않고 기다린다** (fail-closed). 고치면 이어서 돈다.
- 지식베이스 문서를 고치면 재시작 없이 다음 질문부터 반영된다 (임베딩 모델은 다시 읽지 않는다).

## 봇이 어떤 말에 답하나

| 들어온 말 | 답할 근거가 있으면 | 없으면 |
|---|---|---|
| 물음표로 끝남 · `@홍길동` 멘션 | 답변 | **안내 문구** ("확인 후 답변드릴게요") |
| "~되나요" "궁금해요" 같은 의문 어미·표현 | 답변 | **조용히** (기록만) |
| 위에 안 걸려도 지식베이스와 매우 비슷(0.70+) | 답변 | — |
| 그 밖의 말, 4자 미만, 시스템 공지, 내 메시지 | — | **조용히** |

확실한 질문에만 안내 문구를 보낸다. 추측으로 잡은 말에까지 보내면 잡담 중에 봇이 끼어든다.

**같은 사람이 이어 보낸 메시지는 한 질문으로 묶어 한 번에 답한다** (2026-09-26 운영자 결정).
한 번 확인할 때(1분마다) 같은 사람의 메시지가 사이에 다른 사람 말 없이 이어져 있으면 묶는다.

- 답은 그중 **마지막 질문 메시지**에 댓글로 단다 (뒤에 붙은 "감사합니다"가 아니라).
- 질문이 아닌 앞말("수강료가" + "얼마예요?")도 같은 질문으로 본다.
- 여러 가지를 물었으면 한 답에 같이 답한다. **일부만 근거가 있으면 그것만 답하고** 끝에
  "나머지는 확인 후 답변드릴게요."를 붙인다 (`[output] partial_message`). 운영자에게는 답을 못 할
  때와 같은 알림이 간다. 하나도 근거가 없으면 예전처럼 "확인 후 답변드릴게요."
- 검색은 합친 글과 **물음 하나하나**로 따로 하고, 물음마다 가장 잘 맞는 근거를 빠뜨리지 않는다
  (최대 8개). 한 메시지에 여러 줄로 물어도 같다. "환불은" / "언제까지 되나요?" 처럼 끝나지 않은
  짧은 줄은 다음 줄과 이어 한 물음으로 찾는다 (2026-09-26 실전 보완).
- 답에는 질문 번호를 붙이지 않고, 모르는 물음은 아예 쓰지 않는다 (번호만 남은 빈 줄은 보내기 전에 지운다).
- 확인 사이에 걸쳐 보낸 메시지는 다음 확인 때 따로 답한다 — 앞말은 맥락으로 이어 받는다.

**1인 1분 제한은 없앴다** (2026-09-26, `[rate_limit] user_cooldown_secs = 0`). 예전에는 같은 사람이
1분 안에 두 번 물으면 둘째를 답하지 않고 버렸다. 방 전체 상한(1분에 5번)은 그대로다.
어떤 규칙으로 잡았는지는 기록의 `trigger` 에, 왜 넘어갔는지는 `logs/filtered/` 에 남는다.

## 봇을 시작하기 전

카카오톡 창 **두 개**를 열어 둔다. 최소화하지 않는다 (다른 창 뒤에 가려진 것은 괜찮다).

| 창 | 없으면 |
|---|---|
| **대상 방** (채팅 목록에서 더블클릭) | 봇이 시작하지 않는다. 도는 중에 닫히면 기다린다 (아래) |
| **'댓글 알림' 방** (채팅 목록에서 더블클릭) | 스레드 안의 추가 질문만 못 본다 — 방 질문에는 계속 답한다 (운영 로그에 한 번 알림) |

**메인 창(채팅 목록)은 없어도 된다** (2026-09-26 확인 — 메인 창을 닫아도 방 창이 있으면
읽힌다). 예전 문서에 "메인 창을 오픈채팅 탭에 열어 둬야 한다"고 적었던 것은 오류 문구를
잘못 읽은 것이다. openkakao 는 방 창을 못 찾을 때만 메인 창의 채팅 목록으로 방을 열려 하고,
그래서 **방 창이 안 보이면** "could not find KakaoTalk's main chat-list window" 오류가 난다.

두 창은 **지금 쓰는 데스크탑(Space)** 에 둔다. 다른 데스크탑에서 일하려면 Dock 의 카카오톡
아이콘 우클릭 → 옵션 → 지정 대상 → **모든 데스크탑** (아래 '방 창이 화면에 없으면' 참조).

그다음 메뉴바 → 봇 시작. 곧바로 꺼지면 이유가 창으로 뜬다 (대개 방 창이 안 열려 있음).

봇이 답을 달 때는 스레드 창을 잠깐 열었다 닫는다. **운영자가 열어 둔 스레드 창은
건드리지 않는다** (2026-09-24부터 — 봇이 새로 연 창만 쓰고 닫는다).

## 서킷 브레이커

연속 실패 3회면 봇이 스스로 멈춘다. 두 갈래로 센다.

- **읽기** — 방을 못 읽음 (창이 닫힘·최소화 등)
- **답변·전송** — LLM 오류, 전송 실패, 전송 확인 실패

예전에는 하나로 셌는데, 폴링(읽기)이 성공할 때마다 횟수가 0 으로 돌아가 LLM 이 계속 죽어도
멈추지 않았다. 지금은 따로 센다. 멈추면 원인을 고친 뒤 '봇 시작'.

## 방 창을 위로 올려 두면 봇은 읽지 않는다 (2026-09-21)

봇은 방 창에 **보이는** 최근 메시지를 읽는다 (1분 간격이면 창에 올라온 약 48개). 창을 위로 올려 옛 메시지를 보는 동안에는
보이는 것이 최근 메시지가 아니므로 읽지 않는다 (운영 로그: "방 창이 위로 스크롤돼 있어
읽지 않습니다"). **맨 아래로 내리면** 그 사이 올라온 메시지부터 이어서 본다.

예전에는 목록이 바뀌면 화면 전체를 새 메시지로 보고 옛 질문에 다시 답했다
(2026-09-21 15:38 — 같은 질문에 두 번 답함). 그때 원인은 스크롤이 아니라 **카카오톡이
사진 줄을 저절로 깜빡이는 것**이었다 (사진 미리보기를 다시 그리는 3초가량 목록에서 빠짐). 지금은 직전 화면의 마지막 메시지가 안
보이면 아무것도 새것으로 보지 않는다. **사진·파일 줄은 이 기준으로 쓰지 않는다** (2026-09-26 —
사진 줄이 올라가는 중에 자리를 옮겼다가 사라져, 기준을 못 찾은 봇이 그사이 질문 세 개를 넘겼다). 30초(10번) 넘게 안 보이면 기준선을 다시 잡는다 —
그 사이 올라온 메시지에는 답하지 않는다.

(2026-09-20 20:03 에 봇이 멈춘 것을 그때는 "메인 창을 닫아서"로 적었지만, 오류 문구를
잘못 읽은 것이다 — 방 창이 안 보였던 것으로 본다. 위 '봇을 시작하기 전' 참조.)

## 스레드 안의 추가 질문 (2026-09-24)

봇이 단 댓글 아래에 수강생이 다시 물으면 같은 스레드에 답한다 (방에도 함께). '댓글 알림'
창을 신호로 쓴다 — 자세한 동작과 한계는 `docs/followup.md`.

- **'채팅방에 함께 보내기'를 켜고 단 댓글도 방이 아니라 그 스레드에서 답한다** (2026-09-26
  운영자 결정). 방 화면에서 함께 보낸 댓글은 말풍선 위 원글 인용 칸 + 아래 스레드 버튼으로
  가려낸다. 방에서는 넘기고, '댓글 알림'으로 스레드를 열어 함께 보내기를 켜고 끈 댓글을 모두
  읽고 한 질문으로 답한다. '댓글 알림' 창이 없을 때만 예전처럼 방에서 답한다.
- '댓글 알림'에 뜨지 않는 스레드(운영자가 참여하지 않은 다른 수강생 글의 스레드)의 댓글에는
  답하지 않는다.
- 봇이 답한 스레드에 **운영자가 직접 댓글을 달면**, 그 뒤로는 봇이 끼어들지 않는다.
- 한 스레드에 30분 동안 봇이 3번까지만 답한다 (`[followup] max_answers_per_thread`).
- 끄려면 `config.toml` 의 `[followup] enabled = false`. 봇을 다시 띄울 필요 없다.

## 방 창이 화면에 없으면 기다린다 (2026-09-24, 2026-09-26)

봇이 쓰는 접근성 API 는 **지금 보이는 데스크탑(Space)의 창만** 본다. 방 창을 닫거나,
최소화하거나, 다른 데스크탑·전체 화면 앱으로 가면 봇에게는 방이 안 보인다. 예전에는 이때
읽기가 3번 실패해 봇이 멈췄다 (2026-09-24 00:54, 그리고 12:12 — 이때는 이틀 동안 멈춰 있었다).

지금은 **대상 방 창이 안 보이면** 멈추지 않고 기다린다 (2026-09-26 운영자 결정).

- 메뉴바: 🤖💤 "방 창이 화면에 없음" (메뉴바를 2026-09-26 이후 다시 켠 경우)
- 읽기 실패로 세지 않고, 자가진단도 쉰다. 10분 넘게 이어지면 알림을 한 번 보낸다.
- **돌아오면 그사이 올라온 질문에 늦게라도 답한다** (2026-09-24 운영자 결정). 첫 읽기는 창에
  올라와 있는 메시지를 넓게(약 48개) 본다. '댓글 알림'도 20줄까지 본다.
- 늦은 답에도 속도 제한은 그대로다 — 방 전체 1분 5개, 1인 60초. 한꺼번에 많이 쌓였으면
  넘친 질문은 답하지 않고 기록만 남는다 (`rate_limited`).
- 약 48개보다 많이 쌓였으면 그 앞 것은 놓친다 (30초 뒤 기준선을 다시 잡는다).

주의:

- **카카오톡 자체를 끄면** 예전처럼 읽기 실패로 멈춘다 (다시 켜고 '봇 시작').
- **봇을 시작할 때** 방 창이 없으면 곧바로 오류로 알린다 (방 이름 오타·창을 안 연 경우를 바로
  알 수 있게). 다만 카카오톡 창이 하나도 안 보일 때(다른 데스크탑에서 시작)는 보일 때까지 기다린다.
- 긴급 정지 뒤 재개는 다르다 — 그때는 정지 중 질문에 답하지 않는다.

## 폴링 간격 — 1분 (2026-09-26)

방과 '댓글 알림'을 **1분마다** 본다 (운영자 결정 — 실시간일 필요는 없다). `config.toml` 의
`[poll] interval_secs` 로 바꾸며, 바꾸면 다음 폴링부터 적용된다.

- 답은 질문 뒤 최대 1분 + 답 만드는 시간(보통 10~20초) 늦게 달린다.
- 1분 사이 20개 넘게 올라와도 놓치지 않게 매번 창에 올라온 메시지를 넓게(약 48개) 읽는다.
  '댓글 알림'도 매번 맨 위 20줄을 본다 (다른 방 알림에 밀려 내려가도 찾게).
- 쉬는 동안에도 10초마다 상태를 적는다 — 메뉴바가 '응답 없음'으로 보지 않는다.
- 쉬는 중에도 '봇 중지'에는 1초 안에 선다.
- 직전 화면의 마지막 메시지를 못 찾으면 두 번(2분) 만에 기준선을 다시 잡는다 (3초 간격일 때는 30초).

부담 (2026-09-26 실측, 3초 간격 기준): 봇 CPU 0.2%, 방 읽기 한 번 0.07초·CPU 14ms, 봇 때문에
카카오톡이 더 쓰는 CPU 약 0.1%. 카카오톡은 원래 혼자 CPU 7~10%·메모리 약 500MB 를 쓴다.
1분 간격이면 읽기 부담은 20분의 1이다. 더 큰 부담은 첫 질문 때 올리는 검색용 임베딩 모델
(메모리 1GB 이상, 봇이 켜져 있는 동안 유지)이다.


## 텔레그램 알림 켜기

알림이 없으면 봇이 멈추거나 답을 못 해도 아무도 모른다 (2026-09-24 12:12 부터 이틀 동안 멈춰
있었다). 알림은 이럴 때 간다: 답할 근거가 없을 때(일부만 답했을 때 포함), 전송을 확인하지 못했을
때, 서킷 브레이커로 멈췄을 때, 자가진단 실패·복구, 방 창이 10분 넘게 안 보일 때.

1. **예전 토큰 폐기** — 2026-09-18 토큰이 대화에 노출됐다. 텔레그램 @BotFather → `/revoke` → 봇
   선택 → 새 토큰이 나온다. 새 토큰은 어디에도 붙여넣지 않는다 (다음 단계에서 한 번만 입력).
2. **알림 받을 방에 봇 두기** — 개인 대화면 봇을 검색해 `/start`. 그룹이면 그룹에 봇을 초대하고
   `/start` (그룹에서 봇은 명령어만 받도록 되어 있어 일반 메시지는 못 볼 수 있다).
3. **터미널에서 직접** `bash scripts/setup-secrets.sh` — 토큰은 화면에 안 보이게 입력되고, 봇이 들어간
   방 목록에서 고르면(여러 개일 때) 시험 메시지를 보낸 뒤 macOS 키체인에 저장한다. Anthropic API 키는
   `claude-cli` 모드라면 엔터로 건너뛴다. 토큰은 설정 파일에 쓰지 않는다.
4. **봇 경로로 확인** — `.venv/bin/python -m kakaobot --test-notify`. 봇이 키체인에서 설정을 읽어
   "✅ 카카오봇 알림 시험" 을 보낸다.
5. **봇 다시 시작** — 봇은 켤 때(또는 설정 파일이 바뀔 때) 알림 설정을 읽는다.
