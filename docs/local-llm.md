# 로컬 LLM · 파인튜닝 준비

> 결정 D7 갱신 (2026-09-19): **로컬 LLM 실행 도구는 새 Mac 구매 뒤 정한다.**
> 그 전까지 코드는 특정 도구에 묶이지 않게 둔다. 이 문서는 장비가 왔을 때 할 일과,
> 말투 파인튜닝을 위한 데이터 원칙을 정리한다.

## 1. 지금 된 것

| 항목 | 상태 | 위치 |
|---|---|---|
| OpenAI 호환 어댑터 (`LocalAdapter`) | ✅ 가짜 서버로 검증 (연결 실패·시간 초과·HTTP 오류·잘림·생각 과정 제거) | `src/kakaobot/llm.py`, `tests/test_local_llm.py` |
| 보조 백엔드 (`FallbackAdapter`) | ✅ 구현, **기본 꺼짐** | `[fallback]` |
| 말투 지침 (`[style] guide`) | ✅ 시스템 프롬프트에 끼움 (규칙보다 우선하지 않음) | `build_system_prompt()` |
| 점검 명령 | ✅ `python -m kakaobot --check-llm` | `__main__.py` |
| 파인튜닝 후보 추출 | ✅ audit → 검수용 JSONL → train/valid | `scripts/export_finetune.py` |
| 실행 도구 설치 | ⛔ 하지 않음 (결정 대기) | — |

로컬 모드로 바꿀 때 서비스 코드는 건드리지 않는다. `config.toml` 의 `[local]` 을 채우고
`[mode] current = "local"` (또는 메뉴바 → 모드 → 로컬)로 바꾸면 된다. `[local]` 의
`endpoint`·`model` 이 비어 있으면 설정 오류로 멈춘다 — 빈 설정으로 조용히 실패하지 않게.

## 2. 새 Mac 이 오면 — 체크리스트

1. 실행 도구를 고른다 (§3 비교표). 파인튜닝까지 할 계획이면 **학습 결과를 그 도구가 그대로
   올릴 수 있는지**가 가장 중요한 기준이다.
2. 모델을 올리고 서버를 **127.0.0.1 에만** 연다 (LAN 공개 금지 — 익명 입력이 들어가는 모델이다).
3. `config.toml`:
   ```toml
   [local]
   endpoint = "http://localhost:8080/v1"   # 도구별 주소는 §3
   model = "<서버가 /v1/models 로 보여주는 id 그대로>"
   ```
4. 점검: `.venv/bin/python -m kakaobot --check-llm` — 서버 연결, 모델 로드, 근거대로 답하는지,
   근거 없으면 `답변불가` 하는지, 지시 주입을 따르지 않는지를 한 번에 본다.
5. 인젝션 회귀: Phase 1-D 공격 3종을 로컬 모델로 다시 돌린다 (모델이 바뀌면 방어도 다시 확인).
6. 응답 시간 확인: 방의 분당 질문 수 × 응답 시간이 폴링 주기를 넘지 않는지.
7. 모드 전환 → dry-run 으로 하루 → 실제 전송.

## 3. 실행 도구 비교 (고를 때 참고)

| 도구 | 기본 주소 | 모델 id 예 | 생각 과정(thinking) 끄기 | 파인튜닝 결과 올리기 |
|---|---|---|---|---|
| MLX-LM (`mlx_lm.server`) | `http://localhost:8080/v1` | HF 저장소 경로 | 채팅 템플릿 옵션 / 프롬프트 지시 | `mlx_lm.lora` 로 학습한 어댑터를 같은 생태계에서 바로 사용 |
| LM Studio | `http://localhost:1234/v1` | 앱에 표시된 id | 앱 설정 / 모델별 옵션 | MLX·GGUF 모델 파일을 불러옴 (학습은 별도 도구) |
| Ollama | `http://localhost:11434/v1` | `qwen3:32b` 형식 | 모델·버전별로 다름 | GGUF 변환 + Modelfile 필요 |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` | 파일 이름 | `extra_body = { chat_template_kwargs = { enable_thinking = false } }` | GGUF LoRA 어댑터 (`--lora`) |

- 모델 후보는 계획서 §2 (Qwen3.6-35B-A3B 1순위, gpt-oss-120b, EXAONE 4.5 — **EXAONE 은 비상업 라이선스**).
- 도구별 차이(생각 끄기, top_p 등)는 코드가 아니라 `[local] extra_body` 로 맞춘다. 요청 JSON 에 그대로 합쳐진다.
- 표의 옵션 이름은 도구 버전에 따라 바뀐다 — 설치할 때 그 버전 문서로 다시 확인한다.

### 생각 과정(thinking)을 켜 두면 생기는 일

추론 모델은 답 앞에 생각 과정을 길게 쓴다. 어댑터가 `<think>…</think>` 를 걷어내고
`reasoning_content` 필드는 쓰지 않지만, 생각이 `max_tokens`(700)를 다 쓰면 답이 잘린다.
잘린 답은 **보내지 않고 오류로 센다** (`finish_reason=length`). 오픈채팅 안내에는 생각
과정이 필요 없으니 끄는 쪽을 권한다. 응답 시간도 크게 준다.

## 4. 보조 백엔드 (fallback) — 운영 결정 필요

```toml
[fallback]
enabled = false        # 지금은 꺼 둠
to = "claude-cli"      # 로컬이 죽으면 claude -p 로 한 번 더 묻는다
```

- 넘기는 경우: **연결 실패·시간 초과·서버 오류·빈 답·잘린 답**만. `답변불가`나 출력 검증 차단은
  판단이므로 넘기지 않는다 (다른 모델에 다시 물어 답을 받아내면 근거 원칙이 무너진다).
- 트레이드오프: 파인튜닝한 로컬 모델이 죽었을 때 클라우드로 넘기면 **그 답만 말투가 다르다.**
  넘기지 않으면 질문자는 안내 문구(D11)를 받는다.
  - 응답률 우선 → `enabled = true, to = "claude-cli"`
  - 말투 일관성 우선 → `enabled = false`
- audit 의 `mode` 에 `local→claude-cli` 처럼 남으므로 어느 쪽이 답했는지 추적된다.

## 5. 파인튜닝 원칙 — 말투를 가르치고 사실은 가르치지 않는다

이 봇의 사실은 **RAG 근거에서만** 온다 (계획서 §1). 파인튜닝은 그 위에 말투만 입힌다.

1. **사실을 모델에 넣지 않는다.** 수강료·환불 규정은 바뀐다. 모델에 넣으면 지식베이스를
   고쳐도 옛 값을 말한다. 학습 예제도 반드시 `<근거>` 를 보고 답하는 형식으로 만든다.
2. **추론 때와 같은 형식으로 학습한다.** 시스템 프롬프트 + `<근거>` + `<최근_대화>` +
   `<user_message>` 그대로. audit 에 `context`·`history`·`system_sha` 를 남기는 이유다.
3. **거절도 가르친다.** 근거가 없을 때 `답변불가` 하는 예제를 섞는다 (추출 스크립트는 10%
   미만이면 경고한다). 답만 가르치면 튜닝 뒤 근거 없이 지어내는 쪽으로 기운다.
4. **인젝션 거절을 지우지 않는다.** 튜닝 뒤 §2-4 의 점검과 인젝션 회귀를 반드시 다시 돌린다.
5. **LoRA 로 한다.** 원본 모델은 그대로 두고 어댑터만 바꿔 끼운다 — 비교·되돌리기가 쉽다.

### 말투 데이터는 어디서 오나

| 출처 | 장점 | 주의 |
|---|---|---|
| 봇 답변을 운영자가 고친 것 (`export_finetune.py`) | 형식이 추론과 똑같다 | 원래 말투가 Haiku 말투 — **운영자가 고쳐 써야** 말투가 옮겨진다 |
| 운영자가 방에서 직접 한 답 (카카오톡 '대화 내보내기') | 진짜 운영자 말투 | 질문–답 짝을 맞추고 근거를 붙이는 작업이 따로 필요 |

### 흐름

```
logs/audit/*.jsonl (30일 뒤 삭제)
   └─ scripts/export_finetune.py        → data/finetune/candidates.jsonl
        (닉네임→'질문자', 전화·이메일 치환, 중복 제거, RAG 단계 에스컬레이션·검증 차단 제외)
   └─ 운영자 검수: 나쁜 줄 삭제, assistant 답을 원하는 말투로 고치기
   └─ scripts/export_finetune.py --finalize → data/finetune/train.jsonl, valid.jsonl
        ({"messages": [...]} 채팅 형식 — 대부분의 LoRA 도구가 읽는다)
```

- audit 는 30일 뒤 지워진다. 그 안에 추출하지 않으면 사라진다.
- `data/finetune/` 은 **자동으로 지워지지 않는다.** 익명 참여자의 질문이 들어 있으므로 보관 기간을
  정해야 한다 (운영 결정).
- 수백 개 이상 모이기 전에는 형식 확인용으로만 쓴다.
